RESEARCH EXPERIMENT CODE

Install from the repository root:

  python -m pip install -e '.[experiments,test]'

The library and historical research CLI are installed from src/. Additional
research experiments use the source-checkout modules in experiments/lib/ and
experiments/runners/. Commands below are run from the repository root.

Entry points

  experiments/runners/synthetic.py
      Bounded-logit diagnostics, sampling, and resource proxies.
  experiments/runners/pretrained.py
      Pretrained attention, normalization, depth, and perturbation diagnostics.
  experiments/runners/recall.py
      Paired native-scaling, Frobenius-scaling, and uniform recall models.
  experiments/runners/long_recall.py
  experiments/runners/long_recall_routing.py
      Mean-matched long-context recall, with classification-only and disclosed
      matching-index auxiliary training, evaluated through length 8192.
  experiments/runners/reevaluate_long_recall_caps.py
      Matched cap24 checkpoint reevaluation for the native cap24/cap64 comparison.
  experiments/runners/recall_8192.py
  experiments/runners/recall_8192_recovery.py
      Training through length 8192 and cap24 recovery recipes. Recipe selection
      uses validation; evaluate_recall_8192_final.py opens the reserved test
      after select_recall_8192.py freezes the choice.
  experiments/runners/mqar.py
  experiments/runners/mqar_variance_init.py
  experiments/runners/mqar_standard.py
  experiments/runners/mqar_cap.py
  experiments/runners/mqar_cap24.py
      Official MQAR data with capped, ordinary Transformer, initialization,
      cap-sensitivity, and matched uniform-attention cohorts. The coordinator
      run_mqar_cohort.py runs all fixed seeds for one attention variant.
  experiments/runners/recovery_extension.py
      Fixed SST-2 cohorts with an internal checkpoint-selection partition.
  experiments/runners/recovery_search.py
      Exploratory additional seeds with explicit selection policies.
  experiments/runners/recovery_large.py
      Large-backbone recovery and recorded training scope.
  experiments/runners/recovery_low_rank.py
      Low-rank updates capped after composition with the base matrix.
  experiments/runners/recovery_full_dense.py
      Dense continuation with all model parameters trainable.
  experiments/runners/recovery_guided.py
      Disclosed teacher-guided continuations and training-data mixtures.
  experiments/runners/recovery_sam.py
      Gold-label sharpness-aware continuations with exact parameter restoration.
  experiments/runners/selective_layer.py
      Explicit selective-attention construction and full-layer checks.

Use --help for each runner. Protocols and pinned configurations are under
experiments/configs/{mqar,recall,recovery,diagnostics,selective_attention}/. Fixed cohorts, exploratory searches, and
continuations have distinct protocols and must not be pooled as independent
training seeds. A continuation requires its recorded parent checkpoint; those
checkpoints are supplied separately. Pass --checkpoint-root for the relative
parent paths in a recovery recipe; use --assets and --teacher for prepared
inputs. Output and result directories are explicit arguments, including in
comparison and reporting scripts.

experiments/README.md maps every later recall/MQAR cohort to its entrypoints,
protocols, configurations, and reproduction commands. The original Zoology
generator and license are retained in experiments/vendor/zoology/ alongside
UPSTREAM.json; both files must match their recorded Git blob hashes.

Example: fixed SST-2 cohort

  python experiments/runners/prepare_recovery_assets.py \
    --config experiments/configs/recovery/recovery_extension_low_lr.json \
    --output ./reproduction-assets/sst2
  python experiments/runners/run_recovery_extension.py \
    --config experiments/configs/recovery/recovery_extension_low_lr.json \
    --assets ./reproduction-assets/sst2 --output ./reproduced/recovery_low_lr

The coordinator uses two GPUs. Use recovery_extension.py for one
model/device, specifying --model, --mode, --seed, --assets, --config, --output,
and --device. Configurations describe the full planned cohorts; canceled or
unfinished attempts in a historical execution are not successful results.

Example: associative recall without external model/data downloads

  python experiments/runners/recall.py \
    --config experiments/configs/recall/recall.json --output ./reproduced/recall

The default config uses cuda:0; save a separate config to change its device.
The model is small, uses generated data, and evaluates fixed final checkpoints.

Tests

  python -m pytest -q

Most tests use tiny CPU models or synthetic fixtures. A GPU-specific test may
skip on CPU-only hosts. The distribution test requires the build package from
the test extra. Full dense Mistral training additionally uses bitsandbytes;
the individual run manifests record the actual runtime package versions.

Focused recall/MQAR checks:

  python -m pytest -q tests/test_long_recall.py tests/test_mqar.py \
    tests/test_mqar_standard.py tests/test_mqar_caps.py

These cover paired-data invariants, dense attention equivalence, causality,
official-generator equivalence, matched initialization, and cap enforcement.

Recorded outputs and release tools

Completed metrics, per-example predictions, and figure source tables are
committed under artifacts/. See artifacts/README.md for inventory checks and
reaggregation commands. Checkpoints, raw tensor datasets, and downloaded models
are omitted. The pre-existing evidence snapshot in
src/quantum_friendly_transformer/evidence is a separate historical resource.

The summarize_* and validate_* runners take explicit result directories.
summarize_mqar_predictions.py also reads the committed cohort ZIPs directly.
tools/verify_experiment_records.py checks compact prediction tables and source
hashes without model inference. tools/summarize_cap_results.py extracts
matrix-norm evidence from the historical archive and supplied new audit tables.
tools/build_research_bundle.py packages separately supplied experiment records
and optional checkpoints from an explicit --results directory. A code-only
checkout cannot regenerate missing results
or restore omitted checkpoints by running an aggregation script.

Training manifests record source checksums and the exact configuration for
each run. Keep those manifests with the corresponding checkpoints and results.
