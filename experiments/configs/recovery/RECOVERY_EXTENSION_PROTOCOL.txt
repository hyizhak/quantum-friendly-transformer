BOUNDED-DENOMINATOR RECOVERY EXTENSION

Purpose
-------
Extend the configured-alpha-floor SST-2 recovery regime with multiple seeds,
uniform-attention controls, and separate checkpoint selection and evaluation.
Targets: TinyStories-1M, 8M, and 33M, all unsuccessful in the archived bounded
run collection. All newly completed runs, including failures, are retained.

The fixed alpha_s constants are copied from the effective values of the
corresponding archived bounded runs. Caps and alpha_w remain 24. The learned
denominator can increase above alpha_s^2*alpha_w^2 and cannot decrease below it.
There is no native-temperature warmup or unrestricted scale optimization.
Uniform attention sets all queries to zero and preserves the existing masks.

These are scalar-floor experiments. The historical alpha_s constants are not
certified bounds on the attention-input matrices. We measure full padded input
matrix Frobenius norms at every selection evaluation and final evaluation.
Exceedances are recorded explicitly. Measurements on selection batches are
not a uniform bound over all inputs or all intermediate training steps. The
native pre-LN/multihead architecture and normalization parameters are retained.
These experiments do not validate the complete theorem model or show quantum
advantage. No stronger claim is inferred from an SST-2 recovery threshold.

Design
------
Pinned public model and data revisions are in recovery_extension.json.
Models: TinyStories-1M, 8M, 33M. Modes: bounded and uniform. Seeds: 42,43,44.
The initial classification head and training example order are paired within
each model and seed across modes. All model parameters are eligible to train.
No teacher model, added training corpus, or extra classification features.
The classifier pools the final unmasked token using the existing decoder wrapper.

Each run uses the official SST-2 training corpus with a fixed 10% group split
for checkpoint selection. Identical sentences, after case/whitespace
normalization, stay together. Exact sentence matches to official validation
are removed from training and selection using text only. No sentence-family
or source-document grouping is available, so related phrases may occur across
the training and selection partitions. Official validation supplies the final
872-example evaluation and does not select checkpoints in these new runs.
It has been used by historical experiments, so this is not a newly collected,
globally untouched test set. Split indices and their hashes are saved.

Sequences are right-padded/truncated to 128. Padding is not counted as evidence
of long-context routing; average visible lengths are saved. The models have
native causal/local masks; at this tensor length the local window is not smaller
than the context. Bound diagnostics include all rows of the padded matrix,
which also upper-bound the Frobenius norm of any visible-key subset.

Optimization uses float32 master parameters with bfloat16 autocast on CUDA,
AdamW, and a cosine schedule after 6% linear warmup. This differs from the
archived bfloat16-parameter runs and preserves finer optimizer updates. The
batch size is 32. Base learning rates are 3e-4,2e-4,2e-4, respectively, with
budgets 20000,10000,6000 updates. All bounded runs use per-layer controllers,
a dedicated learning rate 0.01, epsilon 1e-12, and zero controller weight decay.
Model weight decay is 0.01. Controller and other gradients are separately
clipped to norm 1. The bounded controller is projected after every update and
also clamps its effective multiplier during each forward. Its recorded scale
is checked against the fixed alpha floor at selection and final evaluations.

The full selection set is evaluated at step 0 and every 1000 updates, including
the final step. The checkpoint with highest selection accuracy is saved;
lower selection NLL breaks ties, and an exact tie retains the earlier checkpoint.
The complete predetermined budget is run, with no recovery-based early stop.
The saved checkpoint is reloaded before the final official-validation evaluation.

The historical validation targets are 0.823394495412844,0.8337155963302753,
0.8451834862385321, respectively. A run meets the historical recovery criterion
when its final-evaluation accuracy is at least target minus 0.01. These targets
are inherited one-seed baselines, not new matched native baselines, and the
criterion is not a statistical equivalence test. Report each seed and the mean
and sample standard deviation, alongside all matched uniform-control runs.

Implementation validation
-------------------------
Tests verify train/selection/evaluation sentence separation, actual tiny-HF
backbone training with a bounded controller, checkpoint round trips, diagnostic
output preservation, and uniform attention with the original causal/local masks.
A short GPU smoke run validates the compiled AMP training path and is excluded
from experiment results. Compilation accelerates the same specified model;
no selection or hyperparameter decision is based on smoke accuracy.

Reproduce from the repository root
----------------------------------
python experiments/runners/prepare_recovery_assets.py --output ./assets/recovery
OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 HF_HUB_OFFLINE=1 TOKENIZERS_PARALLELISM=false TORCHINDUCTOR_CACHE_DIR=./cache/inductor python experiments/runners/run_recovery_extension.py --assets ./assets/recovery --output results/recovery_extension

The coordinator uses cuda:0 and cuda:1. A single run can be launched on any
device using recovery_extension.py with --model, --mode, --seed,
--device, --compile, --assets, and --output. Select a new output directory for
repetition. Existing successful coordinator entries are skipped; incomplete
outputs cause an error and are preserved for inspection.

Each run saves the actual config, split, training/selection histories, norm and
scale diagnostics, selected checkpoint, final predictions, result, and source/
asset hashes. Downloaded pretrained weights and raw dataset files live outside
the result directory and can be reconstructed from pinned revisions.

Exploratory lower-learning-rate follow-up
-----------------------------------------
After the first complete runs of the initial cohort fell below their historical
thresholds despite high training/selection accuracy, a second full cohort was
specified in recovery_extension_low_lr.json. The sole optimization change is
a tenfold reduction in the model learning rate: 3e-5,2e-5,2e-5. Controller
learning rate, data split, seeds, step budgets, masks, scalar floors, and checkpoint
selection remain unchanged. The purpose is to test gentler adaptation with
float32 master parameters. Every model/mode/seed combination is retained in
both cohorts; the follow-up is not presented as a blind confirmatory study.
Protocol choice was informed by early official-validation results of the first
cohort. Final benchmark scores therefore remain exploratory even though each
individual run selects checkpoints only on its internal selection set.

Run with the coordinator's --config option and a distinct --output directory,
results/recovery_extension_low_lr. Do not pool seeds across the two
learning-rate settings or report only whichever setting gives a better score.

--------------------------------------------
